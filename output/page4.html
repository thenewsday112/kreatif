Tom Foley: How to pair typefaces and why the best brand fonts go unnoticed

📅 Oct 21, 2026  |  Category: Entertainment  |  Read Source →

Tom Foley didn’t set out to design typefaces. As a postgraduate student at Central Saint Martins in London, he was researching why Ireland, unlike Switzerland, the Netherlands, or Germany, never seemed to have a confident typographic voice of its own.

The answer led him through centuries of colonial history, to a so-called “Irish type” invented during the Reformation to make printed scripture look the way outsiders thought Irish readers would want it to look, and back further still, to fifth-century monks who may have given us the first true lowercase letters and the word space. The best response to that research, Tom realized, was a typeface. He called it Nib, and it now lives on Dublin’s heritage plaques.

That mix of deep research and hands-on craft has defined his career since. Tom worked on the first phase of Netflix Sans, a typeface you may see every day and probably never notice. At Monotype, he rose to Executive Creative Director and led custom work like the National Portrait Gallery’s contemporary serif. This year he walked away from that role to become Creative Type Director at Studio DRAMA, because he wanted to get back to making type.

We talk about how cultural context shapes letterforms, how to balance heritage with something that feels modern, and Tom’s practical framework for pairing typefaces, which starts with calligraphic roots and vertical metrics rather than vibes. We also get into why he left a prestigious executive role, how a childhood struggle with reading may have sharpened his eye for letters, and the books and typefaces he thinks every designer should know.

Bio

Tom Foley is Creative Type Director at Studio DRAMA in London, where he designs custom typefaces for brands. He was previously Executive Creative Director at Monotype, where his work included a custom serif for the National Portrait Gallery and his typeface Cotford. Before that, he spent years at Dalton Maag, working on multi-script projects for Nokia and the first phase of Netflix Sans. Tom came to type design through research: his postgraduate thesis at Central Saint Martins on Irish typographic history produced Nib, the typeface now used on Dublin City Council’s heritage plaques.

Short version: Tom Foley is Creative Type Director at Studio DRAMA in London and former Executive Creative Director at Monotype. His work spans custom typefaces for Netflix, Nokia, and the National Portrait Gallery.

Declarative design means creating the rules your design should follow, instead of deciding exactly how it looks in every situation. This might seem like a radical way to do UI design, but it’s pragmatic in a world where we’re building products that have to work on so many devices and screen sizes. 

Watch the hands-on live session where I demo these concepts.

Fixed navigation vs responsive navigation (using breakpoints) vs declarative navigation.

Declarative design helps us focus on the design intent rather than getting caught up in unrealistic pixel-precise renderings. And it helps designs translate so much better into code. You can read more on the declarative design approach compared to other approaches (with examples!) in What is declarative design and why is it the future?

But what has declarative design got to do with Penpot? As Pablo Ruiz-Múzquiz, Penpot’s CEO, wrote in his article on The missing ingredient in design tools: declarative design:

CSS has evolved to be a powerful declarative design language. Best of all, it’s ubiquitous. What if a design tool decided to express design concepts like alignment and layout using CSS as its foundational abstraction?

Penpot was created with declarative design in mind; it utilizes web standards, CSS properties and layouts so you can design as code, and your design looks exactly the same in the browser as it does in Penpot. Let’s have a look at the specifics.

CSS Grid and Flexbox

Penpot provides a visual way to design CSS Grid and Flexbox (Flex) layouts without needing to know the code. The properties (like direction, alignment, justification and flex-wrap!) are the same as CSS so your designs don’t just translate, you’re designing as code. You can even do complex grid layouts with cells spanning multiple columns and rows, and named grid areas.

A grid in Penpot mixing fr and auto units for a responsive layout.

Design tokens

Declarative design is a way to think in systems, creating rules and exceptions. Design tokens fit perfectly into these declarative systems. Giving names to reusable variables describes their design intent. Tokens can reference other tokens, creating interconnected systems where you can update multiple design decisions by changing a single value.

Editing the body.strong typography token in Penpot. You can see the token applied in the Text styles in the Design panel.

Design tokens use the Design Tokens Community Group (DTCG) format, an open standard created to work as code or in design.

Other CSS properties 

It’s not just layouts and tokens that are CSS in Penpot, each property in the Design panel maps directly to a CSS property or SVG object. Any Penpot user can open the Inspect tab to get the code for the element selected on the canvas.

Inspecting the navigation link shows all the relevant CSS properties in the Inspect panel.

The Styles and Computed options show the element’s relevant CSS properties in an easily readable (and copy-pastable) format. The Code option shows the element’s raw HTML, CSS, and SVG (great for vector shapes like icons).

Built to work with code

Penpot’s code is ready to use or build upon, you can create your own integration with Penpot’s API or Penpot’s MCP server (to connect Penpot to AI workflows), or use an existing Penpot plugin that provides the functionality you need. No more handoffs (please!)

Declarative design can really improve the process and relationship between design and development. Too often we’re faced with a “handoff,” where a designer throws a mockup at a developer, and a developer attempts to interpret it into code. The developer is irritated because the design choices are hard to translate into working code. The designer isn’t happy with the final output because it doesn’t look anything like their original design. There’s never enough time to iterate or collaborate on how to rectify this tension.

When designers use declarative design, it fits much better with coding practices, and takes advantage of the flexible medium of the web. It creates a shared language where no translation or handoff is needed.

Find the CSS Grid code for the layout grid in the Inspect panel.

With Penpot, developers get the unambiguous code they always wanted, and designers get their true design intent in the final product. Us designer-developers can work with a tool that reflects how we think in code. Nobody resents each other, collaboration gets faster, and everyone lives happily ever after. (Well, we can dream!)

You’re migrating from Figma to Penpot, hello and welcome! You’ll probably find that many features feel familiar from other design platforms, but there are key differences. And sometimes it’s just the case that you’re looking for a specific feature but it has a different name in Penpot. I’ve written this cheatsheet covering the differences in terminology for you!

Boards

Penpot Figma Boards Frames

One of the biggest but simplest differences between Figma and Penpot is the containers you use on the canvas for organization and layout. Penpot calls these boards. You can create a board from the board tool in the toolbar or using the shortcut B.

Creating a board from the toolbar.

Colors, typography, and design tokens

Penpot Figma Assets Styles Colors Color styles Typographies Text styles Design tokens Variables Design token sets Collections Design token themes Modes

Where Figma has Assets and Styles, in Penpot, you store Colors, Typographies and Components under the Assets tab. This is also where you can publish your stored assets as Libraries to share with your team.

Find components (and any Colors and Typographies) in the Assets tab.

Colors and Typographies are a handy way to save colors and text styles for reuse later, but you can also store them as design tokens. Design tokens don’t just support colors and typographies, but spacing, dimensions, shadows, and much more. Penpot’s design tokens are similar to Figma’s variables, however they natively use the W3C Design Tokens Community Group format so they work easily with any other tool that shares this format.

While you can organize Figma’s variables into Collections, Penpot’s design tokens have sets, which you can selectively apply to create themes. Themes are a little like Figma’s Modes, but in Penpot themes you can combine sets across a group, and several groups can be active simultaneously.

Find Tokens and design token themes in the Tokens tab.

Layouts

Penpot Figma Flex layout Auto layout Absolute (positioning) Ignore auto layout Fit content Hug contents Guides Layout guides

In Penpot, you can choose between Flex layout and Grid layout for automated flexible layouts. Flex layout is similar to Figma’s auto layout, but Penpot takes its properties (as well as its name!) from CSS Flexbox. Penpot’s Grid layout uses the same properties as CSS Grid. This means that as you’re designing your layouts, you’re creating them as code. They work exactly the same way as they do in the browser, and any user with any role can get the CSS properties or code from the Inspect tab.

Flex and Grid layouts work exactly as they do in a web browser.

Following the CSS Flexbox properties and values, Penpot uses “Fit content” to describe when a layout is automatically sized to its contents, not “Hug contents” like Figma. And when you want an element to ignore its flex or grid parent layout? Look for the Absolute positioning option in the element’s layout properties.

Guides in Penpot can be columns, rows, or an old-school square grid, as well as rulers. You might know these as “layout guides” in Figma.

Inspect

Penpot Figma Inspect Dev Mode

If you’re a developer you might recognize more terminology here: in Penpot we “Inspect” our designs, rather than moving to a different Dev Mode as in Figma. Inspect is found in the workspace or View mode, and any user can access the properties and code for the selected element on the canvas.

Inspect the Flex layout board and viewing its code.

View mode

Penpot Figma View mode Present / Play prototype

Similar to Figma’s “Present” or “Play prototype” options, Penpot has View mode. View mode is where you can share or present your designs, as well as testing your prototypes. While in View mode, you can also generate (and destroy) share links, leave comments, and inspect the design’s code.

Use the play button to launch View mode.

Community resources

And if you’re looking for community resources, check out the Penpot Hub for a whole variety of libraries, templates and plugins.

Moving your whole team over?

Now you know what the features are called, you can start moving your designs across. If you’re thinking bigger than a personal project, Penpot works for enterprise teams too, however large or distributed you are.

Designers and developers work in the same place, and designs are built on the same CSS foundations developers already use. That means less time translating between design and code, and more time building. You can also host Penpot on your own servers, so your data stays under your control.

Kevin Flores has been part of the Design Better community for years — we first met him in 2017, while he was leading design at 23andMe, back when we were researching how design teams are structured for the Design Genome Project. How Milton Glaser set design quality standards

📅 Oct 09, 2026  |  Category: Technology  |  Read Source →

In graduate school, Randy Hunt spent weeks on a poster for Milton Glaser’s class. He built an image entirely from hand lettering, so it read as a picture from across the room and as words up close. Glaser pointed at it and said, “Well, that’s not very good,” and moved on to the next student.

Ouch! Randy tells the story fondly. He went on to apprentice in Glaser’s studio, then led design at Etsy, Grab, and Notion, and he chairs the MFA Design program at the School of Visual Arts. Glaser played a huge role in shaping Randy’s sensibility as a designer, and his standards for quality.

Eli and I talked with Randy about what that standard looks like inside a software company. His answers apply whether you lead a team or want to join a better one.

Set a high bar and good people get better

Quality standards are often framed as a bar to aspire to, but Milton Glaser had a quality floor, a baseline of excellent he expected from his studio and from his students. Randy compares it to teaching to the top of the class.

Randy brings the same approach to his own teams. Put five or six excellent designers together, especially ones who keep their egos in check, and each of them improves faster than they would alone. Everyone’s work raises what the others expect of themselves.

“Keep the floor really high so that the ceiling can get higher.”
—Randy Hunt

Dan Harden described the same kind of mentor when he told us about working for George Nelson. Nelson, he said, “was always striving for the apotheosis, the very best you can do,” and he refused to compromise on the design while others argued about cost. Both Dan and Randy describe a mentor whose standard became their own.

George Nelson is regarded as one of the most important figures in American design. Active as an architect, a product and exhibition designer and a writer, he was a leading voice in the discourse on design and architecture over several decades.

“The objective should be to keep improving one’s basic product.”

—George Nelson

Glaser was generous as well as demanding. Randy calls him a “communication philosopher” who cared about how people feel about things. He remembers the bowl of fresh fruit Glaser kept in the studio, gesture of hospitality to all who visited the studio.

Context Libraries: How AI Power Users Manage Context Engineering

📅 Oct 09, 2026  |  Category: Technology  |  Read Source →

Summary: Claude power users rarely edit their context files and often can’t find them. Your AI agent is only as powerful as its context library.


AI agents have made curating context as important as writing prompts. The agent can do the typing, but deciding what context to keep, where to put it, and when to update it is left entirely to the user — and even the experts are struggling. This is true for UX professionals as much as for the Claude power users from various industries in our recent study . Our participants spent more effort engineering context libraries than crafting prompts (most of which they casually dictated). Yet each had improvised a bespoke process, files went stale or missing, and many suspected that someone else was surely doing it better.

What Is a Context Library?

A context library is a collection of institutional and procedural knowledge, contained within markdown files or external software, that AI agents may reference and edit.

A context library does not live solely within markdown files, though this was certainly the prevailing file type used to store context by our participants. MCP and API connections expand the library to include external sources such as Notion databases, Slack histories, or Granola transcripts. Some context in the library is actively updated and maintained; some is merely referenced.
